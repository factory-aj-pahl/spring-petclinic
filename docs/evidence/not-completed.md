## Limits of this evidence

- **Attribution.** The agent worked through the `factory-aj-pahl` account with the Factory Droid App's user token, so GitHub shows that account as the author of every commit and of the pull request. The `Co-authored-by: factory-droid[bot]` line in each commit, the pull request description and this package identify the agent's work; the account name alone does not. GitHub does not let the author of a pull request approve it, so an approving review has to come from another collaborator.
- **The hook is a guardrail, not an access control.** It checks the text of the commands that Droid runs with its Execute tool. It does not see what a script file does, what other tools do or what a person does, and it lets a command through when it cannot read its input. The one-time push to `main` (decision 7) ran from a script file on purpose, which shows this gap. Only branch protection on GitHub can enforce a review, and this repository has none (F13).
- **Approval through the session.** The approver answered in the Factory session, not on GitHub. The questions, answers and times come from the session transcript: `raw/session/session-evidence.txt` was extracted from it by `scripts/session-evidence.py`. The transcript is not in the archive, because it contains the whole working session; Factory can provide it.
- **Where the tests ran.** Everything except the GitHub checks ran in the agent's sandbox, not in CI. The times come from the sandbox clock, which agrees with the times GitHub recorded for the workflow runs (`raw/github/runs-after-seed.txt`).
- **Evidence from earlier commits.** QA run 1 tested `f9bbb32` with the QA skill before it was committed, and the first findings probe tested `7a27efc`. The final test run, QA run 2 and the second probe tested `407b5f3`.
- **Guard check.** In the worktree for `500158f`, the git-commit-id plugin read the main checkout's Git directory and recorded `d120c42` instead of `500158f`. Only the jar's Git information is affected; the guard test reads the library versions from the jar manifests.
- **Reachability** of the advisories is the agent's reading of the advisory texts against the code. It is labeled Inferred or Unknown in `docs/DEPENDENCIES.md`.
- **Redactions.** Before the archive was built, `scripts/redact-session-ids.py` replaced the HTTP session ids in `raw/findings-probe-final/h2-probe.json` and `h2-probe.txt` with `<redacted>`, as they already were in `raw/findings-probe/`. The scripts that extract from the session transcript replace tokens with `[REDACTED]`. Each probe checked that its generated database password appears in none of its output files. `scripts/credential-scan.py` then found no tokens, keys or session ids in the archive (`raw/credential-scan.txt`). The archive does contain the approver's name and work email address, because Git and the build record them; every commit's sign-off contains them too. Otherwise the raw files are as the tools wrote them, some under a new name, and the checksums in `raw-evidence.sha256` are of the archived files.
